# 产品需求与验收

版本：首版 0.1.0。本文整理已确认的需求及当前首版边界；未来新增能力需明确调整范围。

## 目标与术语

用户配置输出位置、常用密码和递归方式后，选择输入并启动，自动完成识别、还原、伪加密检查、密码尝试、递归与结果整理。正常流程无需逐层确认；密码不匹配时等待用户补充。

- **一个逻辑输入**：一个普通文件，或用户一次选中的同组全部分卷。
- **隐写/伪装压缩包**：本项目首版特指改后缀，或在压缩数据前拼接图片等载体；不包含像素级隐写。
- **伪加密**：加密标记被修改但条目数据没有真正加密；不能根据标记本身判断修复成功。
- **一层**：解开一个压缩包的层级。还原后缀、剥离载体、合卷、伪加密修复、展开包装目录不额外计层。
- **分支**：本层包含多个可继续解压的包时，各自形成独立递归路径；总层数为最大深度。

## 功能与验收规则

| 编号 | 已确认要求 | 验收结果 |
| --- | --- | --- |
| R01 | Windows / macOS 桌面应用，用户无需安装 Python 或解压工具 | Windows x64 单文件 EXE；macOS 14+ Apple Silicon / Intel 分别提供 APP 压缩包 |
| R02 | 一次一个逻辑输入，不支持顶层批量 | 拖入多个独立压缩包、目录、符号链接或重复文件时明确拒绝 |
| R03 | 同组分卷必须一起拖入或选择 | 校验同组编号和已知缺卷；不自动读取源目录未选中的分卷；缺少末卷可能由引擎发现 |
| R04 | 支持 ZIP、RAR3/RAR5、7z | 普通包与伪装包都继续；无有效支持格式时提示无法解压 |
| R05 | 先识别二进制结构，再还原格式 | 不仅看扩展名或单个魔数；在副本中剥离前缀、规范格式后缀 |
| R06 | 在密码尝试前处理伪加密 | 首版仅修复 ZIP bit 0；本地头、中央目录或两者被修改均需覆盖；完整数据及 CRC 校验通过才保留修改 |
| R07 | GUI 管理常用密码 | 密码默认明文显示；添加、编辑、删除、UTF-8 TXT 导入后立即保存，无需另点保存；每行一个密码，保留内部和首尾空格，保存失败明确提示 |
| R08 | 自动依次尝试密码 | 先探测无需密码情况，再尝试去重的非空密码；成功密码在本任务后续层优先；全失败给出可行动提示 |
| R09 | 补充密码后继续 | 当前窗口复用任务及已成功层；错误密码不算成功；真实加密不被伪修复破坏 |
| R10 | 两种深度 | `one` 只解一层，`auto` 按下表递归；默认 `auto` |
| R11 | 四种输出位置 | 源目录直接、源目录新建文件夹、固定目录直接、固定目录新建文件夹；默认源目录新建文件夹 |
| R12 | 两种产物保留方式 | 默认只要最终结果；可选保留 `_中间产物/`，含还原包、修复副本及各层解压结果 |
| R13 | 最终内容容易访问 | 自动展开包装目录、保留沿途 TXT；保护内容本身的目录结构 |
| R14 | 保护用户文件及可选清理 | 原始输入默认保留；开启删除后，仅在结果成功发布后删除本次选中的原文件/全部分卷；输出重名不覆盖；解压失败/取消保留原件及缓存 |
| R15 | 长任务可观察、可取消 | 右侧展示过程日志与双进度条：整体运行阶段、当前包解压百分比；保留完成/等待密码/失败状态及结果或缓存入口；解压不阻塞界面线程 |
| R16 | 文件名编码作为配置项 | 支持默认、自动检测、截图中的常用语言代码页和 UTF-8；配置持久化并应用各层旧 ZIP；GUI 和 CLI 共用逻辑 |

### 界面与进度（2026-10-13 确认）

- 左侧上方为拖拽/选择文件区，下方为配置、密码管理入口和运行按钮；右侧日志占据主要高度，分隔条可调节两侧宽度，小窗口左侧可滚动。
- 输出位置四选一、递归方式二选一、产物保留二选一、原文件保留/完成后删除二选一，全部平铺为圆点单选按钮。文件名编码保留每次选一项的下拉框，初始为“默认”，已有保存选择继续回读。
- 使用简短功能文案，删除宣传口号。浅色背景、文字、选中项和弹出菜单应在系统深色主题下仍清楚可读。
- 密码输入、列表和编辑框均明文显示。修改后立即保存，关闭或 Escape 不撤销已保存修改；未点击添加的输入不自动加入密码库。保存失败时保留窗口内修改并显示失败状态。
- 第一条为整体运行状态指示，配合识别、复制/还原、合卷、检查、解压、整理等阶段文字，不虚构递归任务的总百分比。
- 第二条显示当前包、当前密码尝试的解压百分比。密码检查时显示等待解压，重试和切换包时重置；只有解压及结果检查成功后为 100%。取消/失败不能显示任务成功。
- 7-Zip 读取真实进度输出；中文 ZIP 密码兼容回退按读取的未压缩字节计量。很快的小文件可能直接从 0% 跳至 100%；未能得到更细进度时不使用计时器伪造百分比。
- 日志记录当前文件、层数、阶段、密码尝试序号及成功密码；密码中的换行、回车、制表符在日志中以转义形式显示，实际密码保持原值。
- 磁盘日志沿用缓存生命周期：失败/取消保留，成功后随缓存清理，不新增永久日志归档。

### 解压完成后删除原文件（2026-10-13 新增）

- 左侧“原文件”提供“保留原文件”和“解压完成后删除”，默认保留；配置持久化，旧配置缺少字段时为关闭。
- 仅在全部所需分支解压、结果整理/发布及完成记录写入成功之后删除，失败、等待密码或取消不会提前删除。仅解一层模式完成该层即可视为本次解压完成。
- 直接删除本次选中的原文件；同组分卷逐个删除选中的全部卷，不扫描其他文件，不删除包含它们的源目录，也不另行删除输出中的内层压缩包或保留的中间产物。
- 删除前核对文件类型、文件身份、大小与修改/状态时间；预检查有异常时保留整组选中原文件。每次删除前再次核对，避免误删处理期间被替换或改变的文件。
- 解压结果已成功写入后，删除失败按清理警告处理，不触发重复解压；保留结果入口及缓存日志，逐个记录失败路径。分卷删除不是原子操作，部分文件可能已删，其余保留。
- 删除阶段开始前仍可取消清理；真正开始逐个删除后完成这一短清理步骤，不在卷间中断。删除了任意输入后禁用“再次解压”，要求重新选择文件。
- CLI 沿用本机配置，提供 `--delete-sources` / `--no-delete-sources` 覆盖当前调用。

### 文件名编码规则

新增需求来源：用户提供解压软件“代码页”菜单截图。该设置用于文件名乱码，不是界面语言、文件内容编码或密码编码。

- 默认值为 `default`，保持已有引擎行为；旧配置缺少字段时兼容加载。
- 手动支持日语 CP932、简体 GBK/CP936、繁体 CP950、韩语 CP949，Windows-1252/1250/1251/1254/1253/1256/1255/1257、泰语 CP874 和 UTF-8。
- 对 ZIP 缺少明确 Unicode 信息的条目应用选择；UTF-8 标记及 CRC 有效的 Unicode Path 字段优先。已有正确名称不能被用户选择的旧代码页破坏。
- 自动模式按每个 ZIP 独立推测；严格 UTF-8 优先，其次采用受限候选编码检测。有歧义时保留默认并提示，不承诺任意短名称、同包混合编码一定可识别。
- 仅操作副本中的文件名元数据，压缩/加密数据及原件保持不变；支持与伪装、伪加密、分卷、密码重试及递归组合。
- RAR/7z 继续使用引擎自身名称处理，首轮不提供旧 RAR 非 Unicode 名称的手动代码页覆盖。
- 失败后修改代码页再继续，必须重新从原始输入解压，保留旧过程缓存；代码页未变时继续复用成功层。
- 名称无法按指定编码完整解读时给出更换编码的提示；仍执行路径越界和链接检查。

### 递归判定顺序

先忽略系统附加文件，再展开只有一个子目录且旁边至多有 TXT 的包装目录，保留沿途 TXT。如果选择 `one`，在此完成目录整理后结束。

默认 `auto` 按真实内容判定，分卷视作一个包：

| 解压后的有效内容 | 当前分支行为 |
| --- | --- |
| 单个普通/伪装压缩包 | 继续相同识别、还原、修复、密码流程 |
| 多个文件，全部为压缩包 | 各包分别继续 |
| 压缩包 + 普通 TXT | 保留 TXT，继续所有压缩包 |
| 单个普通非压缩文件、仅 TXT 或空目录 | 结束 |
| 出现图片、音视频、程序等其他内容 | 整层保留并结束，不挑出其中的压缩包继续 |
| 展开包装目录后仍有内容子目录 | 保留本层目录结构并结束，不任意打散目录 |
| 后缀及内部标记匹配的 DOCX/XLSX/PPTX、EPUB、APK、JAR 等 ZIP 容器 | 在递归中视为最终内容，结束本层 |

普通 `.txt` 与改名为 `.txt` 的压缩包要通过内容识别区分。文件夹包装展开阶段的 TXT 当前按扩展名分类，这是实现边界；特殊样本需回归后再调整。

示例：`外层.zip → 包装目录/内层.7z → 视频.mp4` 最终直接得到视频；`外层.zip → 内层.zip + 说明.txt` 保留说明并继续；`外层.zip → 内层.zip + 封面.jpg` 停止，两个文件都保留。

### 分卷与结果整理

- 数字分卷支持 ZIP/7z，例如 `.zip.001`、`.7z.001`。
- RAR 支持 `.part1.rar`、`.part01.rar` 等，以及 `.rar + .r00` 老式分卷。
- PKZIP 支持 `.z01 + .zip`，需处理跨盘偏移和中央目录，不能当作普通字节拼接。
- 分卷需保留可识别的同组编号；支持首卷前置载体。不承诺每卷分别改名或分别拼接载体的非标准样本。
- 同名纯文件自动改名。包含资源目录的整组内容发生冲突时，使用独立结果文件夹，避免单独重命名 `assets/` 破坏引用。
- 忽略 `.DS_Store`、`__MACOSX`、`Thumbs.db`、`desktop.ini` 和 `._` 前缀文件。

## 配置、失败及安全边界

- 密码库只保存在本机 JSON，目前没有系统钥匙串或加密存储；不上传。按 2026-10-13 用户确认，界面及磁盘过程日志显示成功密码，例如“密码（xxx）验证成功，后续层将优先尝试。”；失败候选值、错误和任务清单仍不写密码。
- 中文等非 ASCII ZIP 密码由 7-Zip 尝试失败后，补充同一密码的 UTF-8 字节尝试；其他格式仍由完整 7-Zip 引擎处理。
- 密码错误与加密数据损坏不总能区分，提示必须保留这种不确定性。
- 未识别格式、缺卷、算法不支持、写入权限或磁盘问题应说明原因；失败后可打开缓存。
- 成功后清理任务缓存；失败/取消或原文件清理未完成时保留。仅支持本窗口中的任务续接，应用重启后不能自动恢复。
- 拒绝越界路径、符号链接、硬链接及 Windows 保留设备名；不执行解压出的程序。
- 自动模式有 64 层、10,000 包的异常递归保护。这不是磁盘配额，解压仍需要足够空间。
- 开发构建尚未正式签名或公证；不能承诺下载后无系统验证提示。

## 自动构建与发布（2026-10-13 新增）

- `main` 有新推送（直接提交或合并 PR）时，自动执行 Windows x64、macOS Apple Silicon、macOS Intel 的源码测试、构建与成品验证；全部成功后创建 GitHub Release。
- Release 使用提交 UTC 时间和短提交号生成唯一标签，指向本次构建提交。最新提交（通常为合并提交）的标题和正文作为主描述，按 Markdown 展示；本次推送中新增提交的完整备注保留在折叠区。首次创建 `main` 时只收录该次最新提交，附完整提交链接。
- 附件为 Windows EXE、两种 Mac ZIP 和 SHA-256 校验文件。上传全部完成后才公开；中断时保留草稿供同一次工作流重跑，已公开的同版本不重复发布或替换附件。
- `dev` 推送、PR 和手动运行只构建验证；发布规则须随代码进入 `main` 才会生效。不自动合并分支，不改变应用内版本号、正式签名或公证配置。

## 首版范围之外

顶层批量任务、自动补选源目录分卷、像素隐写、RAR/7z 特殊伪加密修复、在线密码库、生成密码穷举、跨重启自动恢复、Linux 桌面发行、正式签名/公证均未实现。未来需求不能仅因为出现在此列表就自动视为已获确认。
